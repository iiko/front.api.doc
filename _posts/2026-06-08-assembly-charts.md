Начиная с API V10Preview2 плагины могут получить технологическую карту блюда: состав, нормы закладки, технологию приготовления и изображение. Это позволяет, например, показать повару полную информацию о блюде прямо на кухонном экране.

### Методы

В [`IOperationService`](https://iiko.github.io/front.api.sdk/v10/html/T_Resto_Front_Api_IOperationService.htm) добавлены методы:

* `GetAssemblyChartsForProduct(IProduct product)` — возвращает все версии технологических карт продукта, в том числе недействующие;
* `TryGetCurrentAssemblyChartForProduct(IProduct product)` — возвращает действующую на текущий момент технологическую карту или `null`, если такой нет. Метод также доступен как метод расширения `product.TryGetCurrentAssemblyChartForProduct()`;
* `TryGetAssemblyChartImage(IAssemblyChart assemblyChart)` — возвращает изображение технологической карты в виде массива байт или `null`, если изображения нет. Формат изображения (png, jpg и др.) зависит от того, что было загружено в iikoOffice.

Технологическая карта считается действующей, если `DateFrom` не больше текущего момента, а `DateTo` не задана или не меньше текущего момента. Карта без `DateFrom` действующей не считается.

Технологические карты загружаются с сервера iikoRMS при каждом вызове, поэтому для работы методов нужна связь с сервером. Не вызывайте их в цикле для всего меню — запрашивайте данные по мере необходимости.

### Лицензия

Методы требуют наличия лицензии на модуль **«iikoFront: API технологических карт»** (id модуля 21108101). Без лицензии методы выбрасывают `InvalidOperationException`.

### Типы данных

Типы находятся в пространстве имён `Resto.Front.Api.Data.Assortment`.

`IAssemblyChart` — версия технологической карты:

* `Product` — продукт, которому принадлежит карта;
* `DateFrom`, `DateTo` — период действия версии; `DateTo == null` — без ограничения;
* `AssembledAmount` — выход готового продукта в единицах измерения продукта;
* `TechnologyDescription` — технология приготовления;
* `Description` — описание блюда;
* `Appearance` — внешний вид;
* `Organoleptic` — органолептические показатели (вкус, запах, консистенция);
* `OutputComment` — комментарий к выходу;
* `HasImage`, `ImageId` — наличие и идентификатор изображения;
* `ProductSizeAssemblyStrategy` — способ учёта размеров блюда: `Common` — одна карта для всех размеров с коэффициентами, `Specific` — отдельные строки ингредиентов для каждого размера;
* `Items` — список ингредиентов.

`IAssemblyChartItem` — строка технологической карты:

* `Product` — ингредиент;
* `AmountIn` — брутто;
* `AmountMiddle` — нетто (после холодной обработки);
* `AmountOut` — выход (после холодной и горячей обработки);
* `ProductSize` — размер блюда, к которому относится строка; `null` — строка относится ко всем размерам;
* `SortOrder` — порядок строки в карте.

Количества указаны в единицах измерения ингредиента. Чтобы получить вес в килограммах, умножьте значение на `UnitWeight` продукта. При стратегии `Specific` фильтруйте строки по `ProductSize`.

Технологические карты ингредиентов не загружаются автоматически: если нужно раскрыть вложенные полуфабрикаты, запросите карту для каждого ингредиента отдельно. Циклические ссылки между картами сервер не допускает.

### Нормы приготовления блюда

Кроме того, в [`IProduct`](https://iiko.github.io/front.api.sdk/v10/html/T_Resto_Front_Api_Data_Assortment_IProduct.htm) добавлены свойства `CookingTimeNormal` и `CookingTimePeak` (`TimeSpan?`) — нормальное время приготовления и время приготовления в час пик, заданные в карточке блюда. Если норма в карточке не задана, свойство возвращает `null` — в этом случае используется норма типа места приготовления ([подробнее]({{ site.baseurl }}{% post_url 2026-10-02-cooking-place-type-cooking-times %})).
